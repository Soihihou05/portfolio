# Project Showcase

Transform real technical projects into attractive and credible portfolio presentations.

## Project philosophy

A recruiter should understand a project in less than 30 seconds.

Every project should answer:

1. What is it?
2. Why was it built?
3. What did the candidate do?
4. What technologies were used?
5. What was learned or achieved?
6. Can I inspect it?

## Project card

Each project card should contain:

- Project title
- Short one-line description
- 3–6 technology tags
- Short personal contribution
- GitHub link when available
- Demo link when available

Avoid putting the entire technical description on the card.

## Detailed project page

Use this structure:

### Overview

Explain the project in 2–4 sentences.

### Context

Why was the project created?

### Objective

What problem does it solve?

### My role

Clearly describe the candidate's personal contribution.

Use precise verbs:

- Designed
- Developed
- Configured
- Integrated
- Tested
- Automated
- Documented
- Researched

### Architecture

If relevant, show a simplified architecture diagram.

Do not create fake architecture details.

### Technologies

Group technologies logically.

### Key contributions

Use 3–6 concise bullets.

### Challenges

Mention meaningful technical challenges.

### Outcome

Explain what was achieved.

### Links

Include:

- GitHub
- Demo
- Documentation

only when actually available.

## Example

For a Cyber Range project:

Title:

"Cyber Range UCA"

Short description:

"Design of an isolated training environment dedicated to OT/ICS cybersecurity."

Possible sections:

- Context
- Objectives
- Global architecture
- My role
- Technologies
- Infrastructure
- Development
- Lessons learned
- Repository

## Visual design

Project pages should use:

- Clean cards
- Architecture diagrams
- Technology badges
- Code screenshots only when useful
- Minimal icons
- Clear typography

Avoid:

- Huge walls of text
- Fake statistics
- Unnecessary animations
- Decorative terminal windows

## Accuracy

Never invent:

- Metrics
- Users
- Performance improvements
- Technologies
- Responsibilities
- Security scenarios

If the user says they designed something but did not implement it, preserve that distinction.
